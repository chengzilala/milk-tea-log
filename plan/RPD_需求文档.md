## 1. 项目概述

### 1.1 定位

用一张照片记录每次喝的奶茶，**不用填表**：AI 认下饮品名，自动定位城市 / 区，收成一枚印章，按月归档并在地图上回看。产品方向是「贴纸册（主）+ 个人印章地图（辅）」；**v0.2.0 先落地印章 + 地图主线，贴纸册在 Phase 3+**。

### 1.2 当前闭环（v0.2.0）

1. **捕获**：一张照片，不做任何前置选择（拍照 / 相册）。
2. **AI + 定位**：识别饮品名，自动填城市 / 区；失败可手填。
3. **确认**：确认卡最多改 1 个字段，点「收进这个月」。
4. **归档**：按月印章网格；地图按坐标回看。

> 后续阶段（暂缓）：抠图成贴纸 → 贴纸卡 → 贴纸册。当前代码不抠图、不生成贴纸。

### 1.3 目标用户

- 每周 ≥2 杯奶茶，18–35 岁
- 会发朋友圈 / 小红书，对花费有点心疼但不想戒
- 早期种子用户：奶茶脑袋、联名收集党、办公室下午茶组织者

### 1.4 当前状态

- 已有（v0.2.0）：拍照 / 相册、AI 饮品名识别（豆包方舟，可切通义）、自动定位城市 / 区（高德）、确认卡、按月印章网格、地图、详情编辑 / 删除、导出 / 清空、本机存储。
- 缺口：贴纸 / 抠图、品牌与价格 / 糖度 / 小料、分类入库、统计页、徽章 / 连续打卡、主题色 / 我的页、AI 额度 / 自带 Key、导入备份、旧 v0.1 数据迁移。
- 竞品参考：奶茶日记（三步引导：捕获 / 奶茶贴纸 / 归档；卡片展示规格、糖分、含糖量；成就页）、奶茶星球（日历首页 / 打卡表单 / 周月年统计 / 我的 / 主题色 / 分享卡）。
- 明确不跟：糖分「超标」评判、控糖承诺、健康同步、消耗 vs 摄入。
- v0.4 设想（成就 / 统计 / 主题色）在 v0.8 起 **暂缓**，不在 v0.2.0 代码内。

### 1.5 不是什么

- 不是健康管理 / 控糖教练（不做精准热量、不做医疗建议、不做「超标」）
- 不是探店社区 / 优惠券 / 商城 / 排行榜
- 地图只做个人存档，不做探店推荐、店铺评分、店铺详情
- 不是只做「拍照识别 + 贴纸」的玩具：印章 / 贴纸都是**记录载体**，最终要沉淀成图鉴与统计

## 3. 详细功能需求

### 3.1 捕获（已实现 v0.2.0）

**需求**：用户只做「拍 / 选」一个动作，进来就能拍。

**交互**
- 捕获页只有一张主卡：「今天喝哪杯？」+ 「拍一杯」（移动端 `capture="environment"` 直接调相机）+「从相册选」。
- 选中后立即进入处理态：显示压缩后的照片 + 三步进度「识别饮品名 / 获取城市 · 区 / 生成印章」。
  - 第三步「生成印章」只是把照片落成印章卡，**不是抠图**；v0.2.0 没有抠图步骤。
- 识别与定位**并行**，两者都结束（成功或失败）后展示确认卡；任一失败都不阻塞。
- 确认卡出现后自动滚动到可见区域；用户可点「重拍」换一张。

**参数**
- 支持 JPG / PNG / WebP（HEIC 由系统相册转码后再选）。
- 单张 ≤20MB；超过提示「图片超过 20MB，换一张」。
- 压缩：预览最长边 1280px / JPEG 0.82；缩略最长边 640px / JPEG 0.78。
- 统一填米白底（`#fffaf4`）再转 JPEG，避免透明 PNG 体积过大。

**边界**
- 非图片文件：提示「请选择图片文件」。
- 浏览器读不了：提示「这张图浏览器读不了，换 JPG / PNG 试试」，保留重试。
- 一次只处理一张；批量导入暂缓（Phase 3）。
- 相机权限被拒：提示改用相册，不反复弹权限。
- 处理中再次选图：新的任务会作废旧任务（用递增 `jobSeq` 丢弃过期结果）。

### 3.2 AI 免填写（核心，v0.2.0 落地「饮品名」）

**「免填写」的定义**：用户**不输入任何文字**（最多改 1 个字段），只点 1 次「收进这个月」。

**识别对象**
1. 杯贴 / 杯套 / 小票上的**饮品名文字**（首选）。
2. 只能看到品牌、看不到品名：`drinkName` 返回空串并降低置信度，**不拿品牌当品名**。
3. 纯饮品 / 无文字：`drinkName` 空、`category = 未知`、置信度 < 0.3。

**识别字段（v0.2.0 实况）**
| 字段 | 来源 | 是否入库 | 说明 |
|---|---|---|---|
| 饮品名 | 杯贴 / 小票 | 是 | 如「伯牙绝弦」；空则确认卡留空 |
| 分类 | 模型返回 | **否（API 返回但未持久化）** | 奶茶 / 果茶 / 咖啡 / 其他 / 未知；本版不展示，去留见 §11 #14 |
| 置信度 | 模型返回 | 是（仅内部） | 只用于「AI 已填 / 猜的」提示，不展示分数 |
| 时间 | 系统 | 是 | 保存时刻，本版不可改（跨月补记暂缓） |

**暂缓字段（Phase 3）**：品牌、价格、糖度、小料、冰量、杯型、评分。本版 Prompt 明确要求模型**不要**输出这些（见 §6.2）。

**置信度分级（与代码一致）**
- `drinkName` 非空且置信度 ≥0.8 → 徽标「AI 已填」，提示「看一眼，不对就改」。
- `drinkName` 非空且置信度 <0.8 → 徽标「AI 猜的」，提示「不太确定，点一下可以改」。
- `drinkName` 为空（含模型认不出）→ 徽标「AI 没认出来」，提示可手动写。
- 请求失败 / 超时（20s）→ 徽标「识别没成功」，提示原因 + 「手动写饮品名也能存」。

**降级链（任何一步失败都不阻塞保存）**
1. 识别成功 + 定位成功 → 四字段预填，直接可保存。
2. 识别失败 / 为空 → 饮品名留空，用户可手填或直接存图卡。
3. 定位失败 / 非 HTTPS → 城市 / 区留空，可手填，照常保存。
4. 识别服务不可用（未配 Key / 超时 / 限流）→ 页面提示原因，仍可保存原图卡。

> Phase 2 只有「手动改」这一条兜底；「最近常喝 3 选 1」与「纠错记忆」属 Phase 3，**不作为本版验收项**。

**边界**
- 多杯同框：本期只记一杯，不拆分、不提示。
- 只认杯贴文字，不认品牌 logo；不把识别结果当外部事实展示。
- 服务端不落盘照片、日志不含图片内容（见 §6.2）。

**隐私**
- 捕获页固定文案：「照片只用于本次识别，服务端不保存；识别失败也可以手动写。」
- 上传链路：本机压缩 → 自有服务端 → 转发**豆包（火山方舟 Ark）视觉模型**（按 `.env` 可切换为阿里云百炼通义千问）；服务端与模型方的数据处理口径必须写进上线前隐私政策（§9）。
- 方舟默认开启「深度思考」，读图 30s+ 会触发 20s 超时；服务端请求体已固定关闭（`thinking: disabled`），改动这条链路时别删。

### 3.3 奶茶贴纸（v0.5.0 已实现）

> **落地（v0.5.0）**：服务端 `/api/cutout` 代理 remove.bg，返回透明 PNG；前端本机 Canvas 加白边与内边距，最长边约 1024px。抠图未配置 / 失败 / 超时时自动降级为原图贴纸卡，不阻塞保存；详情页提供「生成贴纸 / 重做贴纸」手动入口。

**需求**：把照片里的杯子抠出来，做成带白边的贴纸，放进一张深色卡片。

**交互**
- 处理态 → 抠图完成 → 贴纸以「弹出」动效落到卡片中央 → 卡片可点按进入编辑。
- 抠图结果不理想：提供「用原图」（圆角裁切）兜底，不阻塞。

**样式**
- 白边贴纸：透明底 + 8–12px 白色描边 + 轻微投影。
- 卡片：深色底，顶部「**拍一杯** + 日期」，中部贴纸，底部最多 3 项数据（规格 / 糖度 / 价格），可加一句短文案（选填，默认取备注）。
- 卡片比例 3:4；导出分享图 1080×1440。

**参数与体积预算**
- 贴纸入库：透明 PNG，**最长边 ≥1024px**（分享按 1080×1440 排版，**不从 640px 放大**）。
- 归档网格用 640px 缩略；详情用 1280px 原图或 1024px 贴纸源。
- 单条媒体预算：缩略 ≤80KB + 贴纸 ≤300KB；100 条约 ≤40MB，仍在 IndexedDB 可接受范围（§6.3）。
- 贴纸样式版本号 `style: "outline-white-v1"`，便于以后换风格。

**边界**
- 抠图失败 / 主体不明：自动降级为「原图圆角卡片」，并提示可重拍。
- 背景复杂（手、桌面、多人）：允许保留原图兜底，不要求完美。
- 不做品牌 logo 再创作、不生成官方联名视觉。

**隐私（Phase 3 实现时必守）**
- 抠图同样走服务端，**照片会再次上传**；上线前隐私政策须同时写明「识别」与「抠图」两种用途及保存期限。
- 服务端不落盘、不写含图日志；抠图结果只回传前端存本机。

### 3.4 确认卡（已实现 v0.2.0，0–1 次确认）

**交互**

- 字段：饮品名（占位「如：伯牙绝弦」）、城市 / 区（占位「自动定位 / 可手填」）、备注 / 心情（占位「选填」）。

### 3.6 本地保存 / 导出 / 清空（已实现 v0.2.0）

**存储实况**
- IndexedDB：库 `mtl`、版本 `1`、表 `records`；**记录与图片在同一个对象里**（`photoBlob` / `thumbBlob` 直接内嵌），按 `id` 主键、`date` 建索引。
- `localStorage: mtl:settings:v1`：本版只存 `currentMonth`（上次查看的月份）。
- **没有** `localStorage: mtl:records:v1`，也**没有**独立的 `mtl-media-v1` 媒体库——这两条是旧设想 / 规则里的写法，与代码不一致（见 §11 #15）。

**导出**
- 一键导出 JSON：`milk-tea-log-backup-YYYY-MM-DD.json`，含全部记录 + `photo` / `thumb` 的 dataURL。
- 导出文件不含任何 Key、设备令牌或未记录的隐私字段。
- 每条含两张图，文件可能较大，提示「建议在 Wi-Fi 下导出」。

**清空（分两档，避免误删不可恢复）**
| 操作 | 范围 | 是否影响额度 |
|---|---|---|
| 清空记录（本版已实现） | 只清 `records` 表：记录 + 照片 + 缩略图；保留 `mtl:settings:v1` | 不影响（本版无额度） |
| 清空全部本地数据（Phase 4 随额度上线） | 额外清 `mtl:device:v1` 设备令牌与设置；提示「AI 剩余次数会一起丢失」 | 影响，需二次确认 |

- 清空记录二次确认文案：「清空全部 N 枚印章？建议先导出备份。」
- 清空不可撤销；推荐先导出。

**恢复**
- **导入备份暂缓（Phase 3）**；本版只能导出，不能回灌。
- 额度（Phase 4）与设备令牌绑定，清缓存 / 换设备会丢；若不做恢复码 / 登录，须明确「额度丢失不补、不赔」，并在购买页提前写明（§9）。

### 3.8 AI 额度与自带 Key（暂缓，Phase 4）

> **v0.2.0 没有任何额度、设备令牌、Key 托管、兑换码代码**。本节是 Phase 4 的设计稿，不参与本版验收。

**目标**：识别一直可用、平台不亏；先起量，收费只覆盖成本。

**两条通道（并存，由服务端按顺序判定）**

| 通道 | 规则 | 成本归属 |
|---|---|---|
| 自带 Key | 用户在设置页填自己的视觉模型 Key，识别不限次、不扣平台额度 | 用户 |
| 平台额度 | 新设备赠 3 次；1 元 = 30 次；次数不过期 | 平台 |

判定顺序：**自带 Key 已保存且测试通过 → 用用户 Key；否则平台额度 > 0 → 扣 1 次；否则返回 402**。前端不能指定走哪条通道。

**身份**：不做登录。首次打开生成匿名设备令牌 `deviceToken`（UUID，存 `localStorage: mtl:device:v1`），请求头带 `X-Device-Token`；服务端只存它的 SHA-256 哈希。

**交互**
- 设置页新增「AI 识别」区块：`剩余 N 次` / `填自己的 Key` / `兑换码` / `购买次数` / `清除 Key`。
- 识别成功的卡片底部加一行小字显示来源：`AI · 剩 2 次` 或 `AI · 我的 Key`，不干扰主体。
- **402（额度用完）**：保留照片，字段留空，显示「AI 次数用完了」+「去设置」；**不弹窗、不阻塞保存**，走 §3.2 的降级链。
- 填 Key：密码框 →「保存并测试」→ 成功显示「已生效」；失败提示「Key 不对或没有权限」，不保存。
- 清除 Key：二次确认；清除后回到平台额度通道。

**购买与兑换（验证期人工）**
1. 设置页展示收款码图片 + 固定文案「付款后把订单号发到 milktea@example.com（上线前替换为真实联系方式），24 小时内回兑换码」。
2. 输入兑换码 → `POST /api/redeem` → 成功加 30 次；一次性，重复提示「这个码用过了」。
3. 发码：服务端脚本生成 `MTL-XXXX-XXXX` 并标记归属；后续再做半自动化。
4. 退款：**未使用的次数可退**，按剩余次数折算，验证期人工处理；已使用的次数不退。

**参数**
- 免费次数 `3`；次数包 `1 元 / 30 次`（`QUOTA_PACK_PRICE` / `QUOTA_PACK_CREDITS` 可配置）。
- 平台额度每设备每日上限 `30` 次（防刷）；自带 Key 不限。
- 单 IP 每分钟最多 `30` 次识别请求（**与 v0.2.0 现有 `rateLimit` 一致**）。
- 次数包永久有效；**不做订阅、不做自动续费**。

**边界**
- 额度与设备绑定：清缓存 / 换设备会丢失，设置页固定提示；不承诺找回，明确「额度丢失不补、不赔」。
- 上游识别失败**不扣次数**，只有成功返回才扣。
- 平台 Key 只在服务端环境变量；用户 Key 用 AES-256-GCM 加密存储，接口不回显明文，删除即物理删除。
- 隐私：用户 Key 仅用于代其调用视觉模型，须在隐私说明中写明用途并可一键清除。

**接口（Phase 4 设计稿）**
```http
GET    /api/quota       → { remaining, freeGranted, hasOwnKey }
POST   /api/key         { key, provider } → { ok } / 400 invalid_key
DELETE /api/key         → { ok }
POST   /api/redeem      { code } → { ok, remaining } / 400 invalid_code | used_code
POST   /api/recognize   → 200 时附带 quota；额度用完返回 402 { error: "quota_exhausted" }
```

### 3.9 连续打卡与徽章（暂缓，Phase 3）

**需求**：用「可收集、可回看」给持续记录一个轻理由；只做正向里程碑，不做评判、不做排行榜。

**连续打卡**
- 口径：同一自然日有 ≥1 条记录即算打卡 1 天；当天多条只算 1 天。
- 当前连续天数：今天有记录则从今天回溯；今天还没记录则从昨天回溯（当天未喝不算断签）。
- 展示位置：我的页数据卡、统计页顶部一句轻文案；**不做推送催打卡**。

**徽章（达成即点亮，仅本地，固定 6 枚）**
| 徽章 | 条件 |
|---|---|
| 第一杯奶茶 | 首条记录保存成功 |
| 夜猫子认证 | 22:00–04:00 之间记录 1 杯 |
| 四季品茗 | 春 / 夏 / 秋 / 冬各至少 1 杯（显示 x/4） |
| 品牌收集家 | 收集 ≥5 个不同品牌（依赖 Phase 3 品牌字段） |
| 连续打卡 7 天 | 连续 7 个自然日有记录 |
| 20 杯收藏家 | 累计 20 条记录（= 20 杯，与 §11 #4 口径一致） |

- 未点亮：灰显 + 达成条件；已点亮：彩色 + 首次达成日期。
- 徽章状态只存「首次达成时间」，其余由记录实时计算，避免状态不一致。

**边界**
- 不做排行榜、不做好友对比、不做「断签惩罚」、不做积分商城与等级特权。
- 文案温和：断签只显示「今天还没来一杯，随时记」，不出现「失败 / 中断 / 可惜」。
- 批量补记（Phase 3）不得刷连续天数：只按记录的真实日期计算。

### 3.12 印章地图（已实现 v0.2.0，个人存档）

**需求**：把带坐标的记录落到地图上，回看「在哪些地方喝过」；作为印章页之外的第二种归档视角。

**交互（与代码一致）**
- 入口：底部 Tab「地图」（独立页，不在印章页内切换）。
- 进入后默认全国视图；有记录时自动缩放到全部落点（`fitBounds`，最大 zoom 14）。
- 每条带坐标记录落一个印章图标（42×42，有缩略图则显示缩略图，否则「茶」字兜底）；点击弹气泡：饮品名 / 城市 · 区 / 日期。
- 右上角显示「N 枚」；无带坐标记录时显示「还没有带位置的印章。」
- 页面固定说明：「地图只显示你自己的奶茶印章，不做探店推荐。」

**口径**
- **地图展示「全部时间」的带坐标记录**，不受印章页的月份筛选影响。
- 手填城市 / 区但没有坐标（定位失败 / 非 HTTPS）→ 保留在印章页，**不上图**。
- 同一位置多杯会各自落一枚点、可能重叠；本版不做聚合（聚合暂缓 Phase 3）。

**参数**
- 定位仅在新增记录时请求一次（`enableHighAccuracy: false`，超时 12s，缓存 60s）；用户拒绝也能正常保存。
- 逆地理编码：服务端代理**高德 Web 服务 `restapi.amap.com/v3/geocode/regeo`**，只发送坐标、不发送照片；缓存 24h / 最多 500 条。
- 坐标（WGS-84）与城市 / 区只存本机；底图用**高德瓦片（GCJ-02）**，落点前在前端做 WGS-84 → GCJ-02 转换。
- 瓦片取 2 倍高清图（`scl=2`，512px 缩到 256 CSS px）；高德 2 倍图不带文字，另叠一层注记图层（`webst` `style=8`，1 倍图，自带路网 / 路名 / POI）。底图用 CSS 滤镜（反相 + 色相翻转 + 大幅降饱和）压成深色，注记层同步降饱和并提对比，再蒙一层很淡的深蓝；与参考 App 的深色地图观感对齐。
- 地图库 Leaflet 本地引入（`web/assets/vendor/leaflet/`），不从 CDN 拉脚本。

**边界**
- 定位失败 / 无网络：记录照常保存，地图页提示「还没有带位置的印章」。
- 非 HTTPS（如用局域网 IP 打开）：浏览器禁用定位，页面提示「当前不是 HTTPS，iPhone 定位不可用，可手填」。
- 底图瓦片请求会带出视野范围，但不含任何记录内容；记录本身不上传。
- 不做店铺 POI 详情、评分、推荐、路线、打卡排行。

### 3.13 瓶装水 / 日常饮品（暂缓，Phase 5 后续功能）

> 新增需求（2026-10-22）：日常买的瓶装水也要能收进同一套系统。本节只做需求定义，**当前不写代码、不改数据表**。

**需求**

**交互（设计稿）**
- 捕获页不变，仍是「今天喝哪杯？」——文案不改成「喝点什么」以免弱化奶茶定位，由 AI 自动判定类型。
- 确认卡在现有字段外**多一个「类型」小 chips（奶茶 / 咖啡 / 水 / 其他）**，默认由 AI 预判，可一键改；不增加必填。
- 瓶装水的品名：优先用瓶身品牌 + 规格，如「农夫山泉 550ml」「东方树叶 无糖」；规格识别不到就只存品牌。
- 瓶装水默认**不请求定位**（多为家里 / 办公室购买），仍可手动补城市 / 区。
- 归档 / 地图页顶部加类型筛选（全部 / 奶茶 / 水）；默认「全部」，筛选状态记在 `mtl:settings:v1`。

**数据（Phase 5 才加字段）**
- 新增可选字段 `kind`：`milk-tea | coffee | water | other`，空值不写入（旧记录按 `milk-tea` 兜底展示）。
- 统计口径：杯数默认只算奶茶；瓶装水单独一行「水 N 瓶」，不混进奶茶花费与「本月 N 杯」。

**边界（必守）**
- **只做「买过的水」存档，不做饮水健康**：不做每日饮水量目标、不做喝水提醒、不做补水达成率、不做「今天喝够了吗」评判。
- 不采集购买渠道 / 店铺 / 价格对比；不接任何矿泉水品牌官方数据。
- AI 认不出瓶装水时照旧允许空名保存，不新增失败阻塞。
- 瓶装水与奶茶共用同一套贴纸 / 分享卡，不另做一套皮肤。

## 5. 数据模型（v0.2.0 实况）

```js
// IndexedDB: 库 "mtl" / 表 "records"（keyPath: "id"，索引 date）
{
  "id": "mtl_1729500000000_ab12",
  "createdAt": "2026-10-21T15:30:00.000Z",  // ISO 时间
  "date": "2026-10-21",                     // 本地日期，印章页按月筛选
  "drinkName": "伯牙绝弦",                   // 可空，空显示「未命名」
  "city": "上海市",                          // 可空，空显示「未定位」
  "district": "徐汇区",                      // 可空
  "note": "下午写方案，奖励自己",             // 可空，≤200 字
  "lat": 31.18,                             // 无定位为 null
  "lng": 121.43,                            // 无定位为 null
  "confidence": 0.66,                       // AI 失败为 null；不展示分数
  "source": "ai",                           // ai | ai+edit | manual
  "photoBlob": Blob,                        // 预览图，最长边 1280，JPEG 0.82
  "thumbBlob": Blob,                        // 缩略图，最长边 640，JPEG 0.78
  "mime": "image/jpeg"
}
```

`localStorage`：
- `mtl:settings:v1`：`{ currentMonth: "2026-10" }`（本版唯一字段）。

**明确不存在的字段（避免误读）**：`brand`、`product`、`price`、`sugar`、`toppings`、`ice`、`cupSize`、`rating`、`location` 对象、`sticker`、`category`（API 返回但未入库）、`kind`（瓶装水扩展用，Phase 5 才加）。Phase 3 扩展时按「新增可选字段、空值不写入」的原则追加。

**暂缓方案的存储设计（当前不建表、不写代码）**：
- 若把贴纸拆成独立媒体库：库 `mtl-media-v1` / 表 `media`，记录只存 `mediaId`（旧规则写法，Phase 3 迁移时再启用）。
- 额度（Phase 4）：`localStorage: mtl:device:v1` 设备令牌 + 服务端 SQLite。

约束：
- 原图不入库：只留 1280 预览与 640 缩略，均转 JPEG（透明会被填米白底）。
- 位置只到城市 / 区；坐标选填且只存本机；逆地理编码只发送坐标、不发送照片。
- 不存手机号、地址、人脸等不必要信息。
- 导出 JSON 时 Blob 转 dataURL，不导出任何密钥。
- `confidence` 只做交互提示，不对用户显示百分比。

## 6. 技术实现方案（v0.2.0 实况）

| 层 | 方案 | 说明 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS | 零构建；`web/index.html` + `assets/css` + `assets/js`（`app.js` / `recognize.js`） |
| 服务端 | Node + Express | `server/index.js`，端口 `8830`（`PORT` 可配），静态托管 `web/`（html/js/css 设 `no-store`） |
| 存储 | IndexedDB + localStorage | 记录与图片同在 `mtl / records`（Blob 内嵌）；设置存 `mtl:settings:v1` |
| 捕获 | `<input type=file capture>` | 移动端直接调相机；另有相册入口 |
| 压缩 | Canvas `toBlob` | 预览 1280 / 0.82，缩略 640 / 0.78，统一米白底转 JPEG |
| 识别 | 自有服务端 `POST /api/recognize` | 前端不持有 Key；multer 内存存储（≤20MB），转发 DashScope `qwen-vl-max-latest` |
| 定位 | 浏览器 Geolocation + `POST /api/geocode` | 逆地理编码走高德 Web 服务，服务端代理、24h 缓存 |
| 地图 | Leaflet（本地引入）+ 高德瓦片 | WGS-84 → GCJ-02 转换后落点 |
| 限流 | 内存 Map | 30 次 / 分钟 / IP，5 分钟清理一次 |
| 抠图 | 暂缓（Phase 3） | 设计为服务端 `POST /api/cutout`，本版无代码 |
| 主题色 | 暂缓（Phase 3） | 计划用 CSS 变量，4 套色板 |
| 额度 / Key | 暂缓（Phase 4） | 服务端 SQLite + AES-256-GCM，本版无代码 |
| 成就 / 统计 / 分享卡 | 暂缓（Phase 3） | 纯前端派生 / Canvas 导出 |

### 6.1 抠图方案（Phase 3 再实装）

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| A. 服务端抠图（自有） | 手机无压力、效果稳定、易换模型 | 需服务端与上传、单次成本 | **Phase 3 采用（服务端代理形态）** |
| B. 浏览器本地模型（WASM / ONNX） | 照片不出手机、无调用费 | 首次加载数 MB、低端机慢、破坏零依赖 | 正式版再评估 |
| C. 第三方 API（remove.bg 等） | 接入快 | Key / 费用 / 隐私与稳定性 | **v0.5.0 实际接入（Key 只在服务端）** |

> 本版**已实现** `/api/cutout`（remove.bg 代理）；仍**没有**本地抠图模型，首屏体积预算里不含任何模型文件。

### 6.2 接口约定（v0.5.0 实况）

**`GET /api/health`**
```json
{ "ok": true, "aiConfigured": true, "geocodeConfigured": true, "cutoutConfigured": true, "mockAi": false }
```

**`POST /api/recognize`**
- `multipart/form-data`，字段 `image`（单文件，≤20MB，内存存储，不落盘）。
- 成功返回：
  ```json
  { "drinkName": "伯牙绝弦", "category": "奶茶", "confidence": 0.66 }
  ```
- Prompt 约束：`drinkName` 只填具体饮品名，**不要品牌 / 价格 / 糖度 / 小料**；只有品牌没有品名时返回空串并降低置信度；无杯子 / 无文字时 `category = 未知`、置信度 <0.3。
- 错误码：`400 NO_IMAGE`、`503 AI_NOT_CONFIGURED`、`502 AI_TIMEOUT | AI_FAILED`、`429 RATE_LIMITED`。
- 超时：服务端调用模型 20s；前端 `recognize.js` 20s 后 `AbortError` → `AI_TIMEOUT`。
- `MOCK_AI=1` 时返回固定样例 `{ drinkName: "伯牙绝弦", category: "奶茶", confidence: 0.66, mock: true }`，**仅用于本地开发，不计入准确率**。

**`POST /api/geocode`**
- JSON `{ lat, lng }` → `{ city, district, adcode, formatted }`。
- 高德 `restapi.amap.com/v3/geocode/regeo`；缓存 24h / 最多 500 条；未配 Key 返回 `503 GEOCODE_NOT_CONFIGURED`。

**`POST /api/cutout`**
- `multipart/form-data`，字段 `image`（单文件，≤20MB，内存存储，不落盘）。
- 成功返回 `image/png`（透明底），前端再加白边。
- 上游：`api.remove.bg/v1.0/removebg`，`X-Api-Key` 只存在服务端环境变量 `REMOVEBG_API_KEY`。
- 错误码：`400 NO_IMAGE`、`503 CUTOUT_NOT_CONFIGURED`、`502 CUTOUT_TIMEOUT | CUTOUT_QUOTA | CUTOUT_AUTH | CUTOUT_BUSY | CUTOUT_FAILED`、`429 RATE_LIMITED`。
- 超时：服务端 25s；前端 `recognize.js` 25s。
- **降级**：未配置 / 失败 / 超时都不阻塞记录，贴纸卡退回原图圆角卡片。

**暂缓接口**：`/api/quota`、`/api/key`、`/api/redeem`（Phase 4）。

**隐私**：服务端不落盘照片、不写含图日志；识别时转发给 DashScope / 方舟，抠图时转发给 remove.bg，均只用于本次请求。

### 6.3 关键点与性能

- 上传前压到最长边 1280px，降低带宽与费用。
- 识别与定位**并行**（`Promise.allSettled`），两边都结束后再出确认卡；不做「先出贴纸」。
- 归档 / 地图图片用 `URL.createObjectURL`，切月或重渲染前 `revokeObjectURL`，避免内存泄漏。
- 目标：100 条记录（1280 + 640 两张 JPEG）≤ 50MB；归档首屏 < 1s（中端手机）。
- 单次识别成本按 DashScope 实际账单记录；Phase 2 由平台自担，超预算先降图片尺寸 / 换更小模型。
- 本版无抠图、无本地模型，首屏 JS 只有 `app.js` + `recognize.js` + Leaflet（仅地图页需要）。

### 6.4 额度与 Key 存储（Phase 4 设计稿，暂不实现）

服务端 `server/data/mtl.sqlite`：

```sql
devices(device_hash TEXT PK, created_at, last_seen, free_granted INT, balance INT)
user_keys(device_hash TEXT PK, provider TEXT, cipher TEXT, iv TEXT, tag TEXT, verified_at)
redeem_codes(code_hash TEXT PK, credits INT, created_at, used_by TEXT, used_at)
usage_log(id INTEGER PK, device_hash, day TEXT, source TEXT, ok INT, created_at)
```

- `usage_log` 只记次数、来源、日期，不记图片与识别内容。
- 代码位置：`server/lib/quota.js`（设备 / 赠送 / 扣减 / 上限）、`server/lib/keyvault.js`（加解密）、`server/lib/redeem.js`（发码 / 核销）。
- **当前仓库不存在以上文件与表**，Phase 4 才创建。

## 9. 风险与应对

> 标注「Phase 3 / 4」的风险当前未上线，只做预案。

| 风险 | 应对 |
|---|---|
| 识别不准，用户要改一堆 | 置信度分级 + 徽标提示；直接手改；Phase 3 再加最近常喝 / 纠错记忆 |
| 只能认文字、认不出纯饮品 | 允许空名保存为图卡；文案不承诺「AI 精准识别」 |
| 照片上传引发隐私顾虑 | 捕获页明示用途；服务端不落盘、不写含图日志；隐私政策写明转发给 DashScope |
| 第三方模型的数据留存 | 上线前确认 DashScope 的数据处理条款并写进隐私政策；不接受则换模型或本地方案 |
| 服务成本超预算 | 压图到 1280px；IP 限流 30 次 / 分；记录实际账单；超预算换更小模型 |
| 免费额度被刷（Phase 4） | 设备令牌 + IP 限流 + 每日 30 次；**清缓存可重领，验证期接受**，正式版考虑登录 / 恢复码 |
| 清缓存 / 换设备丢额度（Phase 4） | 设置页固定提示 + 购买页写明「额度丢失不补、不赔」；不承诺跨设备 |
| 1 元包被重度使用亏本（Phase 4） | 每日上限 + 成本监控 + 价格 / 次数可配置 |
| 收款码人工发码慢（Phase 4） | 承诺 24h 内发码；后续用订单号自动核销 |
| 个人收款合规（Phase 4） | 验证期限小额；正式上线接商户支付并开票，隐私政策同步 |
| 退款纠纷（Phase 4） | 明确「未使用可退、按剩余次数折算」，保留付款与发码记录 |
| 用户自带 Key 泄露（Phase 4） | AES-256-GCM 加密、不回显、可一键删除；隐私说明写明仅用于代调用 |
| 非 HTTPS 无法定位 | 页面提示可手填；部署阶段必须上 HTTPS（Phase 2 出口） |
| 高德瓦片与 GPS 坐标偏移 | 落点前做 WGS-84 → GCJ-02 转换；不用 GPS 坐标直接打点 |
| 底图瓦片请求泄露隐私 | 瓦片只带视野范围，不含记录内容；地图库本地引入，不接第三方脚本 |
| 地图滑向探店 | 只做个人存档，不加店铺详情 / 评分 / 推荐；文案固定说明 |
| 定位被拒 / 失败 | 不阻塞保存；记录留在印章页，只是不进地图 |
| 同位置多杯落点重叠（Phase 3） | 先接受重叠；Phase 3 再做同位置聚合 |
| IndexedDB 容量 | 图片压到 1280 / 640；导出备份；清空需二次确认 |
| 低端机卡顿 | 归档 / 地图懒加载；缩略 640px；切页释放 Object URL |
| 品牌商标 / 联名风险 | 不做品牌 logo 图标、不生成官方联名视觉、不暗示合作 |
| 变成「只玩一次」的印章玩具 | 归档按月回看 + 地图；Phase 3 用统计 / 徽章补持续动机 |
| 打卡 / 徽章引发焦虑或攀比（Phase 3） | 不做排行、不催打卡、断签文案温和；徽章只做正向里程碑 |
| 成就系统膨胀、维护成本高（Phase 3） | 固定 6 枚，全部由记录派生；不做积分商城 / 等级特权 |
| 统计口径不一致（Phase 3） | 统一按记录 `date` + 本地时区计算；周口径周一至周日 |
| 主题色影响可读性（Phase 3） | 四套固定色板，正文对比度 ≥4.5:1；贴纸卡不随主题变 |
| 分享卡泄露隐私（Phase 3） | 不含备注 / 位置 / 头像；仅用户主动生成 |

## 10. 参考产品「奶茶星球」拆解

> 素材：`inbox/奶茶星球/` 7 张截图（首页日历 / 打卡表单 / 统计 / 我的 / 主题色 / 分享卡）。
> 本节只做取舍参考；标「Phase 3 / 4」的项**当前未实现**。

| 参考页 | 竞品做法 | 我们的取舍 |
|---|---|---|
| 首页日历 | 大月份标题 + 日历 + 「+ 添加一杯」+ 空状态插画 | **不把日历当首页**：本版印章页用「月份选择 + 网格 + 空状态」，主入口仍是「拍一杯」 |
| 打卡表单 | 照片 + 品牌搜索 / 常用品牌 chips + 品名 + 分类 | **Phase 3 部分采纳**：品牌 chips 用于纠错与手填；分类字段是否入库见 §11 #14；价格 / 糖度 / 小料 Phase 3 |
| 统计页 | 本周 / 本月 / 今年 + 累计认证 + 最爱品牌 TOP3 + 最爱口味 + 打卡热力图 | **Phase 3 采纳**：周期切换、最爱口味、热力图；**不采纳**糖分克数、消耗 vs 摄入 |
| 我的页 | 头像 / 等级 + 总杯数 / 品牌数 / 连续打卡 + 成就墙 + 设置 | **Phase 3 采纳**：我的页 + 数据卡 + 徽章墙；等级改为纯文案「认证进度」，不做等级特权 |
| 主题色 | 焦糖 / 抹茶 / 樱花 / 蓝莓 | **Phase 3 采纳**：CSS 变量实现，本地记忆 |
| 分享卡 | 照片 + 品牌标签 + 规格 + 糖度点阵 + 四宫格 + 保存 / 分享 | **Phase 3 采纳**：四宫格 + 糖度点阵；加「拍一杯」水印，不含备注 |
| 健康同步 / 消耗 vs 摄入 | 与健康数据联动，展示「消耗 vs 摄入」 | **不采纳**：与项目红线冲突，不做健康管理暗示 |

**结论**
- 抄「收集结构」，不抄「健康评判」：成就、连续打卡、品牌收集、热力图都只服务「愿意持续记录」。
- 本版只抄「低摩擦记录 + 按月回看 + 地图」；其余需求统一排在 Phase 3 / 4，不阻塞 Phase 2 出口（30 张真实照片验证）。

## 11. 决策记录（截至 v0.9，开发按此执行）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 免填写定义 | 「0 文字输入 + 最多改 1 个字段 + 点 1 次保存」；不做完全无确认自动保存 |
| 2 | 抠图位置 | Phase 3 走服务端（方案 A）；正式版再评估本地模型；本版无抠图 |

| 5 | 视觉与主题 | 米白 + 焦糖单套主题（v0.2.0）；**4 套主题色排 Phase 3**；不做整体深色模式 |

| 9 | 计费形态 | 免费 3 次 + 1 元 / 30 次次数包；不做订阅、不做自动续费；未使用可退（按剩余折算）；**整体排 Phase 4** |
